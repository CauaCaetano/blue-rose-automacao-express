BLUE ROSE Office

A virtual office where 14 AI agents, each with a name and a role, prospect local businesses and assemble the sales package. You approve before anything is sent.

AI agentsWindows app and browser9 of 9 tests passing

Problem

Selling a website and automation to a local business means understanding the business, creating an identity, writing a proposal, building a preview, reviewing and preparing replies. By hand, that takes hours per client.

Solution

A team of agents with defined roles (CEO, sales, marketing and technology) works through a queue: each one gets the task, does its part with AI and hands it to the next.

If the AI fails or there is no key configured, the system logs the error and keeps going in simulated mode.

Result

Each business gets a full package: analysis, visual identity, content, a local ad, proposal, site preview, SEO, automation script and replies. Everything stops at “awaiting approval”: sending is always done by a person.

How it works

  1. Youregister a business in the form
  2. Salesanalyzes its online presence and potential
  3. Marketingidentity, content and a local ad
  4. Saleswrites the proposal and message
  5. TechnologySEO, site preview and automation script
  6. QAreviews and sends back if needed
  7. You approveand send it yourself

Key features

  • Structured output: the AI answers in JSON validated against a schema, so nothing breaks the flow.
  • Persistent queue: every agent's tasks are stored in the database; if the app closes, it resumes where it stopped.
  • Real time: the panel and the 3D office update over WebSocket.
  • Autopilot (server side, off by default): searches real businesses using public data only, with a daily goal, working hours and one search at a time.
  • Safe export: builds the WhatsApp link with the approved message, but you press send.

Technologies

  • Node.js
  • Express
  • WebSocket
  • SQLite (node:sqlite)
  • Claude API
  • Three.js
  • Electron
  • Supabase
  • GitHub Actions

Validation

9 automated tests (the full flow through all 14 agents, autopilot, WhatsApp and the Supabase mirror) running on GitHub Actions. This review fixed a case where the autopilot could start a duplicate search while an agent was walking to hand over a task.

StockMaster

Inventory control for small shops, without a spreadsheet: products, stock in and out with a reason, and a dashboard that warns what is running out.

Problem

In a small shop, inventory lives in the owner's head or an outdated spreadsheet. A product runs out and nobody notices until a customer asks for it.

Solution

A FastAPI and MongoDB API with a React dashboard. Every movement stores its reason and previous balance; taking out more than the stock is refused.

Result

A complete, tested system. During the audit, the low-stock alert, the main feature of the dashboard, never fired: the filter compared against a string. It was fixed and now has a test that keeps the bug from coming back.

How it works

  1. Purchase or salerecorded in the dashboard
  2. APIchecks the balance and the reason
  3. Databasestores the movement and the new balance
  4. Dashboardrecalculates empty and low items
  5. Yousee what to restock before it runs out

What was done to make it ready

  • Low-stock alert fixed with $expr and covered by a test.
  • Demo mode with an in-memory database: runs without installing MongoDB.
  • Third-party tracker removed from the HTML, along with the badge of the tool that generated the base.
  • Clearer dashboard: product name on each movement and prices in Brazilian format.
  • Dependencies cut from 25 to the 10 the code actually uses, plus a step-by-step README.

Technologies

  • Python
  • FastAPI
  • Pydantic
  • MongoDB (Motor)
  • React
  • Tailwind CSS

WhatsApp automations

The two flows that weigh most on a local business: qualifying whoever messages on WhatsApp, and reminding whoever generated a PIX payment and did not pay.

AutomationPython, no dependenciestests passing

Problem

A real-estate agent reads chat after chat to find out who is ready to buy. A shop loses sales because nobody reminds the customer about the pending payment.

Solution

Qualifier: four questions, a scoring rule and a HOT, WARM or COLD summary for the agent. Recovery: after the waiting time it checks the payment and only sends a reminder if it is still pending.

Result

Tested logic, ready to plug in. The integration points (official WhatsApp API and payment status) are isolated in one function each, so adapting it for a client touches a single place.

Validation

  • Automated tests for the scoring rule, the question flow and both recovery outcomes (paid and pending).
  • Bug fixed: a lead answering “just looking for now” (in Portuguese) was scored HOT. Any variation of “just looking” now counts as a weak signal.
  • Try it in the browser: the live demo on the home page runs the same rules.

  • WhatsApp Cloud API (integration point)

Connecting to the official WhatsApp API requires the client's Meta Business account, so real sending is set up in each client's project.

Websites for local businesses

Six example websites, one per niche, with the same structure a client receives: beauty, dental, physiotherapy, personal trainer, salon and restaurant.

WebsitesHTML, CSS and JavaScriptillustrative names and prices

Problem

People searching for a “beauty clinic” or a “personal trainer” in their city choose among whoever shows up on Google. Without a website, the business is not part of that choice.

Solution

Fast pages with hours, services and prices, a direct WhatsApp button and, in the full versions, a quote calculator, booking with real dates and a filterable gallery.

Result

Examples live in Portuguese and English, used as a starting point: the client's site ships with their brand, services and prices.
